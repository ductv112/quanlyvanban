<decisions>
## Implementation Decisions

### Area 1: Send Trigger Architecture

- **D-01:** Async qua BullMQ — route `/:id/gui-noi-bo` chỉ INSERT (qua SP `fn_outgoing_doc_send_to_recipients` đã có) + enqueue job, return 200 ngay với `external_count` để UI biết có job background đang chờ. Tránh UI freeze 30s khi LGSP slow.
- **D-02:** Job granularity = per recipient (1 job per `outgoing_doc_recipients.id` external). Retry độc lập từng recipient; 1 fail không drag 2 còn lại. Job payload: `{ recipient_id, outgoing_doc_id, tracking_id, sender_unit_id }`.
- **D-03:** Enqueue **sau** khi route handler nhận response success từ repo (SP đã COMMIT). Dùng helper `enqueueAfterCommit()` hoặc gọi enqueue sau `await repo.sendToRecipients(...)` trả success.
- **D-04:** Worker concurrency = 3. BullMQ Worker option `concurrency: 3`. Vừa phải để 1 DN burst 10 VB không bị nghẽn, không spam LGSP.

### Area 2: edXML Builder

- **D-05:** Library `xmlbuilder2` — add vào `e_office_app_new/backend/package.json` (dep mới). Type-safe, escape XML tự động (& < > " '), namespace support đầy đủ.
- **D-06:** Attachment encoding: tải file từ MinIO (qua `attachmentRepository` + `streamFileToResponse` helper hoặc `getObject` API) → encode base64 → embed trong `<Attachment><Content>base64...</Content><FileName>...</FileName><FileType>...</FileType></Attachment>` thuộc `<Manifest>`. File >5MB stream nếu RAM constraint, nhưng base64 toàn bộ buffer đơn giản hơn cho v3.2 (6 DN small scale).
- **D-07:** Output edXML = `Buffer.from(xmlString, 'utf8')` truyền vào `form-data` lib (`form.append('edocFile', buffer, { filename: '<doc_code>.edxml', contentType: 'application/xml' })`). KHÔNG ghi disk.
- **D-08:** Field mapping `outgoing_docs` → edXML MessageHeader:
  - `From`: `{ OrganizationId: <sender lgsp_org_code>, OrganizationName: <sender dept.name> }`
  - `To`: `{ OrganizationId: <dest org code từ inter_organizations.code>, OrganizationName }`
  - `Code`: `{ CodeNumber: outgoing_docs.notation, CodeNotation: outgoing_docs.document_code }` (đối chiếu spec QĐ 28)
  - `PromulgationInfo`: `{ Promulgator: outgoing_docs.signer, PromulgationDate: outgoing_docs.sign_date }`
  - `DocumentType`: lookup `doc_types.name` qua `doc_type_id`
  - `Subject`: outgoing_docs.abstract
  - `SignerInfo`: `{ Signer: outgoing_docs.signer, Position: outgoing_docs.signer_position ?? "N/A", Competence: "Trực tiếp" }`
  - `OtherInfo`: `{ PageAmount: outgoing_docs.number_paper, Appendix: outgoing_docs.appendix_text ?? null }`
  - `DocumentId`: UUID generated by `uuid` lib (lưu vào `lgsp_tracking.lgsp_doc_id` placeholder, sẽ overwrite bằng docId LGSP trả về sau send)
  - `TraceHeaderList`: 1 entry `{ Time: NOW, Path: { From: sender, To: dest } }`
- **D-09:** Field optional null → fallback `"N/A"` cho string, `0` cho number. Log warning `pino.warn` để dev biết. KHÔNG reject ở UI (KH chưa quen — UX nhẹ nhàng).

### Area 3: Error Handling & Retry

- **D-10:** Retry policy BullMQ: `attempts: 5, backoff: { type: 'exponential', delay: 30000 }` → delays 30s/60s/120s/240s/480s (BullMQ formula: delay × 2^(attempt-1)).
- **D-11:** Phân loại error retry vs no-retry:
  - **Retry** (network, timeout, 5xx, ECONNREFUSED, ETIMEDOUT) — throw error trong worker job, BullMQ tự retry
  - **No-retry** (4xx LGSP errorCode 10/15/18/19/20/21/22/23) — catch trong worker, UPDATE tracking status='error' + error_message, KHÔNG throw → job complete với error logged, BullMQ không retry
  - **Success** (errorCode=0) — UPDATE tracking status='success' + lgsp_doc_id từ response
- **D-12:** Error map file `e_office_app_new/backend/src/services/lgsp/error-codes.ts` export `const LGSP_ERROR_CODES: Record<string, string>` với 9 mã (0=Thành công, 10=File khong hop le, 15=Sai SystemId hoac SecretKey, 18=Don vi nhan khong ton tai, 19=Don vi gui khong dang ky, 20=Loi he thong, 21=Loi xu ly file, 22=Format edXML khong dung, 23=Don vi nhan da khoa). Class `LgspSendError extends Error { code: string; }` cho structured throw.
- **D-13:** Sau retry exhausted (5 lần) → BullMQ mark job 'failed' + `failedReason`. Worker `on('failed', ...)` listener UPDATE `lgsp_tracking.status='error'` + `error_message='Retry exhausted: <last reason>'`. Outbox event (nếu sau Phase 36 có) cũng sent_status='error'. Admin UI "Gửi lại" defer Phase 37.
- **D-14:** Credential rotation handling: worker job mỗi attempt gọi `await getLgspService(sender_unit_id, env)` — cache đã invalidate-on-write từ Phase 33 → retry attempt kế sẽ tự dùng credential mới. KHÔNG cần kill running job. Document hành vi trong code comment + SUMMARY.

### Area 4: Worker Hosting + UI Tracking

  - Thêm `workers/src/queues/lgsp-send-queue.ts` (Queue init + add helper)
  - Thêm `workers/src/jobs/lgsp-send-worker.ts` (Worker handler + on('failed') listener)

  - Dev: `npm run dev` riêng cho workers module (terminal thứ 3 ngoài backend + frontend)

- **D-16:** UI polling cadence: frontend `setInterval(fetch, 10000)` gọi `GET /api/outgoing-doc/:id/recipients-status` mỗi 10s khi user mở chi tiết VB đi có >=1 recipient pending. Stop polling khi: tất cả recipient không pending HOẶC user rời page.
- **D-17:** Badge state machine (4 state):
  | recipient_type | sent_status | tracking_status | UI Badge | Color |
  |---|---|---|---|---|
  | internal_unit | sent | — | "Đã gửi nội bộ" | green |
  | external_org | pending | pending | "Đang chờ LGSP" | orange |
  | external_org | sent | success | "Đã gửi LGSP ✓" | green |
  | external_org | sent (đã enqueue done) | error | "Lỗi LGSP: {error_message}" | red |
  Tooltip: timestamp `sent_at` + full `error_message`.
- **D-18:** E2E sandbox test cụ thể (gating Phase 34 verification):
  - DN.001 sandbox active (lgsp_agency_config row environment='sandbox' is_active=TRUE — anh đã confirm)
  - User văn thư DN.001 tạo VB đi: notation/code/abstract đầy đủ, signer + sign_date, attachment 1 PDF nhỏ (~100KB)

  - Wait ~30-60s worker → SELECT `lgsp_tracking` WHERE outgoing_doc_id=X → 2 row status='success' + `lgsp_doc_id` populated (UUID từ LGSP)
  - Postman: `GET {sandbox}/v1/getEdoc?docId=<lgsp_doc_id>` với X-SystemId của DN.002 sandbox → return edXML roundtrip match content đã build
  - UI VB đi chi tiết: 3 badge green "Đã gửi nội bộ" + 2 badge green "Đã gửi LGSP ✓"
  - Test error path: tạo VB đi với external recipient có code không tồn tại → worker fail mã 18 → badge red "Lỗi LGSP: Đơn vị nhận không tồn tại (Code 18)"

## Specific Ideas

- **xmlbuilder2 example pattern** (Phase 34 reference):
  ```ts
  import { create } from 'xmlbuilder2';
  const xml = create({ version: '1.0', encoding: 'UTF-8' })
    .ele('EdXML', { xmlns: 'http://www.go.vn/eDoc' })
      .ele('MessageHeader')
        .ele('From').ele('OrganizationId').txt(senderCode).up().ele('OrganizationName').txt(senderName).up().up()
        // ...
      .up()
      .ele('Manifest')
        .ele('Attachment')
          .ele('Content').txt(base64Content).up()
          .ele('FileName').txt(fileName).up()
        .up()
      .up()
    .end({ prettyPrint: false });
  ```
- **form-data lib pattern** (Phase 34 send):
  ```ts
  import FormData from 'form-data';
  const form = new FormData();
  form.append('edocFile', xmlBuffer, { filename: `${docCode}.edxml`, contentType: 'application/xml' });
  form.append('messageType', 'edoc');
  const res = await fetch(`${baseUrl}/v1/sendEdoc`, {
    method: 'POST',
    headers: { 'X-SystemId': systemId, 'X-SecretKey': secretKey, ...form.getHeaders() },
    body: form as any,
  });
  ```
- **BullMQ job data type**:
  ```ts
  export interface LgspSendJobData {
    recipient_id: number;        // outgoing_doc_recipients.id
    outgoing_doc_id: number;
    tracking_id: number;         // lgsp_tracking.id created by SP
    sender_unit_id: number;      // root unit của DN gửi
    environment: 'sandbox' | 'prod';
  }
  ```
- **Worker handler skeleton**:
  ```ts
  const worker = new Worker<LgspSendJobData>('lgsp-send', async (job) => {
    const { recipient_id, tracking_id, sender_unit_id, environment } = job.data;
    const svc = await getLgspService(sender_unit_id, environment);
    const edxml = await buildEdxmlForRecipient(recipient_id);  // helper trong services/lgsp/edxml-builder.ts
    const result = await svc.sendDocument(edxml.buffer, edxml.destOrgCode, edxml.docCode);
    if (result.success) {
      await updateTrackingSuccess(tracking_id, result.lgsp_doc_id);
    } else {
      await updateTrackingError(tracking_id, mapLgspError(result.errorCode, result.message));
      // KHÔNG throw → BullMQ không retry (4xx LGSP)
    }
  }, { connection, concurrency: 3 });
  ```
